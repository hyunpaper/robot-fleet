# 12. 관제 화면 · 에이전트 승인 (큰 틀)

수집하는 데이터로 볼 수 있는 화면, 기준정보를 엮은 MES형 화면, 에이전트 제안을 사람이 승인하는 화면과 그 뒤의 요청 서비스(ControlApi)를 정한다.
API · 스키마 상세는 중간관리, 시안 · 구성도는 하위 작업이 이 문서의 명세를 따른다.

---

## 결정 요약

| # | 결정 | 근거 |
|---|---|---|
| K1 | 화면은 두 면으로 나눈다. **관제 뷰**(읽기, QueryApi)와 **관리 콘솔**(승인 · 조작, ControlApi) | 관제 뷰는 시연 때 터널에 올릴 수 있다(02). 관리 콘솔은 쓰기 · 실행 권한이 있어 어떤 경우에도 공개 경로에 올리지 않는다(10 D5와 같은 원칙) |
| K2 | **ControlApi 신설, QueryApi와 분리** | QueryApi는 읽기 전용 · 공개 가능으로 남긴다. GitHub 토큰 · 좁은 k8s RBAC · 승인 API는 ControlApi만 가진다. 권한이 다른 것을 한 프로세스에 두면 공개 면이 실행 권한을 끌고 나간다 |
| K3 | 에이전트 2종(교착 · 인프라)은 같은 원칙: **규칙이 사실을 만들고, 액션은 열거된 목록에서만, 실행은 사람 승인 뒤** | 04 "M9 액션 공간"의 검증 가능성 논리를 인프라에도 그대로 쓴다 |
| K4 | **규칙 · 검증 · 실행은 ControlApi(클러스터 안), LLM은 클러스터 밖 집 PC 호스트** | 사실은 서버가 만든 스냅샷(id)이라 LLM이 수치를 지어낼 수 없다(검증 0). 에이전트는 DB · Redis · RabbitMQ · Prometheus에 직접 붙지 않는다 |
| K5 | 에이전트는 **장애 조치 경로에 끼지 않는다** | Sentinel 승격 · quorum 리더 선출 · 워커 재배정은 자동이다(07 · 08). 에이전트는 사후 사실 정리와 복구 보조 액션만 |
| K6 | 저장소는 기존 PostgreSQL의 별도 스키마 `control`. 감사 로그는 추가만 가능 | PostgreSQL 단일은 사용자 확정(07). 새 저장소를 늘리지 않는다 |
| K7 | 파라미터 변경은 **다음 run부터** 적용한다. run 도중 변경 금지 | `SimulationStarted.params` 스냅샷이 그 run의 조건이다(03). 도중에 바뀌면 run 비교가 무의미해진다 |

## 2. MES형 데이터: 있음 / 파생 / 추가 수집

지어내지 않는다. 아래에 없는 MES 항목(품목 · 로트 · 납기 · 작업자 · 교대 · 불량)은 **다루지 않는다**. 시뮬레이터에 그 개념이 없다.

| 분류 | 항목 | 출처 · 조건 |
|---|---|---|
| **있음** (적재 경로 있음) | 작업 상태 · 시각(생성 · 배정 · 시작 · 완료) · 배정 로봇 · 계획 경로 길이 · 실제 이동 칸 · 대기 누적 | `task_history` |
| | 로봇 위치 · 상태 · 배터리 이력, 상태 전이 · 위반 | `robot_telemetry`, `robot_status_log` |
| | 충돌 · 교착, run 조건 · 결과 | `conflict_log`, `simulations` · `run_metrics` |
| | 기준정보 구조 | 7개 테이블 DDL. **행이 없다**(db/seed 미작성) |
| **파생 가능** | 작업 → 스테이션 → 설비 → 라인 | 작업 좌표와 `stations (map_id, x, y)` 유일 제약으로 조인. seed 필요 |
| | 설비별 반입 · 반출 실적, 설비 앞 대기 작업 | 위 조인 + 작업 상태 |
| | 스테이션 처리량, 혼잡 히트맵 | 위 조인 / telemetry 칸 변화 + `conflict_log` 좌표 |
| | 리드타임 분해(대기 → 배정 → 이동 → 작업) | `task_history` 시각 4개 |
| | 패턴 대비 실적 | TaskGenerator가 `task_pattern_flows`에서 뽑아야 의미가 있다(지금은 무작위 스테이션) |
| **추가 수집 필요** | 작업 우선순위 | `TaskCreated.priority`는 있으나 `task_history`에 컬럼 없음 |
| | 작업 실패 사유 | `TaskFailed.reason`은 있으나 적재 안 함 |
| | 작업의 스테이션 · 설비 코드 직접 기록 | `task_history`에 컬럼은 있으나 `TaskCreated`가 아직 안 싣는다(03) |
| | 설비 자체의 가동 · 정지 · 셋업 상태, 설비 버퍼 재공 수량 | 시뮬레이터가 설비를 모델링하지 않는다. 넣으려면 03 이벤트 추가가 먼저다. 지금 범위에서는 "로봇 기준 반입 · 반출"까지만 |

## 3. 에이전트 운영 원칙

### 공통

| 원칙 | 내용 |
|---|---|
| 사실은 서버가 | ControlApi의 규칙 모듈이 사실 스냅샷을 만들어 id를 붙인다. 제안은 그 id를 참조해야 접수된다 |
| 검증 0 | 근거에 든 수치가 그 스냅샷에 실재하지 않으면 자동 폐기(04 검증 0과 같다) |
| 액션은 열거 | 액션 id + 인자. 목록에 없는 액션은 접수 단계에서 거부 |
| 승인은 사람만 | 에이전트 키는 `제안 제출`만 가능하다. 승인 · 실행 API는 관리자 세션만 받는다 |
| 실행 직전 재확인 | 제안 당시의 "현재 값"이 실행 시점에도 같을 때만 실행(비교 후 교체). 다르면 만료 처리 |
| 만료 | 인프라 제안은 짧게(사건이 닫히면 만료), 파라미터 제안은 다음 검증 주기까지 |
| 없어도 돈다 | 에이전트 · ControlApi가 꺼져도 시스템 동작은 같다. 부가 기능이다 |

### 교착 분석 에이전트 (M9)

04 "M9 교착 분석 에이전트의 액션 공간"을 그대로 따른다. 원인 분류는 규칙, LLM은 등급 A 13개 안에서 수정안과 근거만 낸다. 실행은 클러스터 밖 집 PC에서 야간 배치로 한다.

| 항목 | 결정 |
|---|---|
| 입력 run | `run_metrics.complete = true`인 run만. 미완료 run은 사실에서 뺀다 |
| 검증 순서 | 04 검증 0~4는 접수 즉시 ControlApi가 한다. 5~6(같은 시드 재실행)은 **집 PC 클러스터의 실제 run**으로 야간에 한다. CI는 빌드 · 테스트만 |
| 승인 시점 | 검증 6을 통과한 제안만 "승인 대기"에 올라간다. 관리자는 결과 수치를 보고 승인한다(README M9 "자동 검증 후 승인") |
| 승인 후 | PR 머지 → 배포 → **다음 run부터 적용**(K7) → 다음 완료 run의 지표로 사후 평가를 A3에 기록 |
| 등급 B | 제안만 표시하고 실행 버튼은 없다. 사람이 구현한다 |

### 인프라 에이전트

| 항목 | 결정 |
|---|---|
| 역할 | 사건을 사실로 정리하고, 허용 액션 후보를 제시한다. **후보는 규칙이 정하고 LLM은 설명만 붙인다.** LLM이 꺼져 있어도 규칙 후보는 뜬다 |
| 사건 원천 | Prometheus(큐 적체, `fleet_dlq_depth`, 워커 정지, DB 재시도, 이벤트 지연, pod 재시작), k8s API 읽기(pod · HPA), Reconcile 보고서, Sentinel 승격 · RabbitMQ 리더 변경 기록 |
| 주기 | 열린 사건이 있을 때만 동작. 야간 배치가 아니다 |
| 실행 위치 | 규칙 · 실행은 ControlApi. LLM 설명은 집 PC(교착 에이전트와 같은 호스트) |

| 등급 | 액션 | 비고 |
|---|---|---|
| **A** (승인 뒤 ControlApi 실행) | I1 EventWorker HPA `minReplicas` 조정 | 1 ~ 3. 상한 3은 고정(02 · 08) |
| | I2 정지 파티션 즉시 재시도 | 시스템 오류 정지(10 §6)를 원인 해소 뒤 바로 다시 돌린다. EventWorker 관리 포트, 클러스터 안 호출 |
| | I3 DLQ 재처리 | 원 큐로 재발행. 조건: 같은 원인 재발 없음, 1회 건수 상한, 한 run 범위. 중복은 워커 영수증이 막는다 |
| | I4 Reconcile 실행 | 읽기 + `run_metrics` 갱신만 |
| **B** (제안만, 사람이 수행) | 앱 pod 재시작, 리소스 request · limit 변경, quorum 멤버 grow(노드 복구 뒤), DEFAULT 파티션 행 이동, 노드 drain | |
| **금지** (선택지에 없음) | Sentinel 수동 승격 · 설정 변경, `min-replicas-to-write` · `WAIT 1`, quorum 큐 타입 · `x-delivery-limit` · 큐 삭제 · purge, Redis FLUSH · 키 삭제 · 맵 해시 · epoch 조작, 해시 체인 · 재주장 관련 일체, DB DDL · DELETE · TRUNCATE · 마이그레이션, FleetController 3대 이상 · HPA 상한 변경, `POST /admin/run`, PV · 노드 삭제, Secret 조회 | 안전성 불변식 · 과반 수치를 건드리는 것은 전부 여기다 |
| 시간 제약 | 장애 조치가 진행 중이면(승격 · 리더 선출 · 재배정 진행 중) 어떤 액션도 실행하지 않는다 | K5 |

## 4. 요청 서비스 ControlApi

### 위치와 흐름

```
 집 PC 호스트 (클러스터 밖)                        클러스터 (fleet-app)
┌────────────────────────┐   제안 제출(에이전트 키)  ┌──────────────────────────┐
│ 교착 에이전트 (야간)   │ ───────────────────────► │ ControlApi               │──► PostgreSQL  control 스키마
│ 인프라 에이전트 (사건) │ ◄─────────────────────── │  규칙(사실) · 검증 · 실행 │──► Prometheus  (읽기)
│ 로컬 LLM (GTX 1660S)   │   사실 스냅샷 조회        │  관리 콘솔 서빙           │──► k8s API     (HPA 패치만)
└────────────────────────┘                           └──────────┬───────────────┘──► EventWorker 관리 포트
                                                                 │                 ──► GitHub (PR 생성 · 머지)
                                         관리자 브라우저(내부망) ─┘
```

```
제안 → [검증 0~4] ─실패→ 자동 거절
          │
          ├(파라미터) → [검증 5~6: 같은 시드 실제 run] ─불합격→ 자동 종결 · 결과 기록
          │                     │
          └(인프라) ────────────┴→ 승인 대기 ─거절(사유)→ 종결
                                     │      └만료→ 종결
                                     승인 → [실행 직전 재확인] → 실행 → 결과 기록 → (파라미터) 사후 평가
```

### 경계 · 저장 · 인증 · 감사

| 항목 | 결정 |
|---|---|
| 서비스 | ControlApi 1개(replica 1, 상태 없음). 업무 쓰기 대상은 `control` 스키마뿐이다. 사실 테이블(01)은 읽기만 한다 |
| 저장 | PostgreSQL `control` 스키마: 제안 · 사실 스냅샷 · 검증 결과 · 결정 · 실행 · 감사 로그 |
| 감사 로그 | 상태 변경마다 1행(누가 · 언제 · 무엇을 · 이전 → 이후 · 결과). ControlApi DB 역할은 이 테이블에 INSERT · SELECT만 |
| 관리자 인증 | 관리자 계정 로그인 세션. 승인 · 거절 · 실행 · run 관리는 이 세션만 |
| 에이전트 인증 | 에이전트별 키. 권한은 사실 조회와 제안 제출뿐이다 |
| k8s 권한 | ServiceAccount의 Role은 `fleet-app`의 EventWorker HPA `patch`와 pod · HPA 읽기만. QueryApi에는 RBAC을 주지 않는다(02 run 관리 결정 유지) |
| GitHub 권한 | 이 저장소의 브랜치 · PR 생성 · 머지에 한정한 토큰. 비밀은 k8s Secret |
| PostgreSQL 장애 시 | 제안 접수 · 승인 불가. 시스템 동작에는 영향 없음(3절 "없어도 돈다") |

### 노출

| 경로 | 공개 범위 |
|---|---|
| 관제 뷰 + QueryApi 조회 · WebSocket | 시연 때만 터널(02 그대로) |
| 관리 콘솔 + ControlApi | **내부 호스트 전용.** 터널에 등록하지 않고, ingress에서 내부 대역(192.168.10.0/24, 호스트) 허용 목록으로 한 번 더 막는다 |
| Simulator `POST /admin/run` · EventWorker 관리 포트 | 지금처럼 인그레스에 올리지 않는다. ControlApi가 클러스터 안에서만 부른다 |
| Prometheus · Grafana 편집 · RabbitMQ 관리 · DB · Redis | 노출 금지(02) |

## 7. 시안 명세 (하위 작업 · 그림)

정적 이미지 시안이다. 코드가 아니다. 맵은 `maps/factory-a.json` 배치를 쓰고, 수치는 "예시"로 표기한다.

| 화면 | 구성 요소 (위 → 아래, 좌 → 우) |
|---|---|
| 공통 틀 | 상단 바: run 선택(runId · 시작 시각 · complete 표시) · 맵 이름 · 버전. 좌측 탐색: 관제(C1~C7) / MES(M1~M5). 관리 콘솔은 별도 틀(상단 바에 "내부 전용" 표시, 탐색 A1~A4) |
| C1 | 중앙 격자 맵(설비 · 스테이션 · 충전 · 주차 범례), 로봇 점(상태색 7종), 교착 칸 붉은 테두리. 우측 패널: 선택 로봇 상세(상태 · 작업 · 경로 길이 · 배터리). 하단: 틱 · 배속 표시 |
| C2 | 상단 수치 카드 4개(가동 로봇 · 시간당 처리량 · Pending · 최근 1분 충돌). 중단: 상태 분포 누적 막대, 처리량 추세선. 하단: 최근 충돌 표 |
| C3 | 상단 run 지표 카드(가동률 · 혼잡 손실률 · 리드타임 p50/p90/p99 · 경로 효율 · 실패율). 중단: 로봇별 Move/Work/Wait/Idle 누적 막대. 하단: 리드타임 분포 |
| C4 | 맵 위 칸별 색(혼잡도), 토글: 통행량 / 대기 발생 / 혼잡도. 우측: 상위 10 병목 칸 표 |
| C5 | 필터(유형 · 해소 방식 · 틱 범위) + 표(틱 · 유형 · 칸 · 로봇 · 해소 · 대기/해소 시간 · "재생기에서 보기") |
| C6 | run 다중 선택. 좌: 조건 비교 표(로봇 수 · 배속 · 맵 버전 · params 차이 강조). 우: 지표 비교 막대 |

| M1 | 표: 작업 id · 상태 · 출발(스테이션/설비) · 도착 · 대기 시간 · 로봇. 상단 상태별 개수 |

| M4 | 패턴 선택 → 흐름 표(출발 설비 → 도착 설비, 계획 비율 vs 실제 비율, 차이 강조) |
